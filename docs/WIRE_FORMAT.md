# Wire format

Normative for every Strata API body, error and stream frame (PLAN L21, §7.5–§7.7, D24).
The contract is `api/openapi.json` (generated by utoipa from the backend, the only JSON
artefact); this page describes how its schemas map onto bytes. Every hex dump below is a
committed golden fixture (`backend/crates/api/tests/golden/*.hex`): the golden tests fail if the
encoder's output, the fixture, or the dump quoted here disagree.

## 1. Media types

| Use | Media type |
|---|---|
| Request and response bodies | `application/vnd.msgpack` |
| Errors (RFC 7807 problem details) | `application/problem+msgpack` |
| Vault export/import | `application/zip` |

**Why these names.** PLAN §7.7 asks for the currently registered MessagePack media type. IANA
registers MessagePack as `application/vnd.msgpack` (vendor tree); `application/msgpack` and
`application/x-msgpack` are unregistered names in informal use. Strata therefore sends and
accepts only `application/vnd.msgpack`; the unregistered names are rejected like any other
type (`415`), so there is one spelling on the wire. Problem details stay
`application/problem+msgpack`: IANA registers no MessagePack problem type, and this name
follows RFC 7807's own pattern (`application/problem+json`, `application/problem+xml`) with the
structured-syntax suffix convention, so a problem body is recognisable by media type alone and
a client can tell an error from a payload without decoding it. It is a distinct type on purpose
(a problem is not a `vnd.msgpack` payload of the operation) and is used only for error
responses. The strings live in one constant per side (`strata_api::wire::MSGPACK` /
`PROBLEM_MSGPACK`, `strata_client::MSGPACK` / `PROBLEM_MSGPACK`) and the generator's spec
reader.

- Requests with a body must send `Content-Type: application/vnd.msgpack` (parameters are
  ignored, the comparison is case-insensitive). Anything else, or a `Content-Encoding` other
  than `identity`, is `415 unsupported_media_type`.
- `Accept` may be absent, `*/*`, `application/*` or name `application/vnd.msgpack`. The most
  specific matching range decides and `q=0` excludes it. Otherwise the response is
  `406 not_acceptable`. Zip downloads (`GET /me/export`) are requested with
  `Accept: application/zip, application/vnd.msgpack;q=0.5` (the MessagePack range keeps
  problem responses acceptable); the generated client does this in `Client::send_zip`.
- Error responses are always `application/problem+msgpack`. That includes errors produced by the
  framework: unknown route (`404 route_not_found`), wrong method (`405 method_not_allowed`),
  malformed path segment (`404 not_found`) and malformed query (`422 invalid_parameter`).

## 2. Values

Encoding is `rmp-serde` on both sides (`to_vec_named`).

| Schema | MessagePack |
|---|---|
| object (Rust struct) | **map keyed by field name**, in declaration order. Never positional arrays. |
| absent optional field | key omitted (`skip_serializing_if`). Decoders treat missing as `None`. |
| `null` | `nil` (`c0`) |
| string | `str` (UTF-8, validated) |
| integer | the smallest MessagePack integer that holds the value (`positive fixint`, `uint 16`, …) |
| number | `float 64` (`cb`) |
| boolean | `c2` / `c3` |
| timestamp (`format: date-time`) | RFC 3339 string, e.g. `"2026-09-21T14:13:20Z"` |
| ID (`format: ulid`) | 26-character ULID string (Crockford base32) |
| bytes (`Binary`, `type: string, format: binary`) | `bin` (`c4`/`c5`/`c6`), never an array of integers |
| unit enum | the variant name as a string (`snake_case`) |
| tagged enum | map with a `type` key naming the variant, then the variant's fields (see §3) |

**Unknown map keys are ignored** on decode, so older clients accept newer payloads and new
optional fields are additive changes within `/api/v1`. MessagePack extension types (including the
MessagePack timestamp extension) are never used and are rejected.

In OpenAPI, Rust `u32`/`u64` appear as `integer` with `format: int32/int64` and `minimum: 0`. The
client generator maps those to `u32`/`u64`.

## 3. Tagged enums

Enums with data are **internally tagged** (`#[serde(tag = "type", rename_all = "snake_case")]`,
struct variants). The contract shows them as `oneOf` with a `discriminator` on `type`: the API
adds the discriminator automatically to any `oneOf` whose members all have a required
single-valued property. The tag is encoded first.

`Shape::Circle { radius: 1.5 }`:

```text
82 a4 74 79 70 65 a6 63 69 72 63 6c 65 a6 72 61
64 69 75 73 cb 3f f8 00 00 00 00 00 00
```

`Shape::Rect { width: 3, height: 300 }`. `300` needs `uint 16` (`cd 01 2c`):

```text
83 a4 74 79 70 65 a4 72 65 63 74 a5 77 69 64 74
68 03 a6 68 65 69 67 68 74 cd 01 2c
```

## 4. Problem details

RFC 7807 fields `type` (a problem slug, not a URL), `title` (fixed per type), `status`, and
optionally `detail` and `instance`. Extension members appear only when relevant:

| Extension | Present for |
|---|---|
| `errors: [{code, pointer?, message}]` | `invalid_body`, `invalid_parameter` |
| `candidates: [DuplicateCandidate]` | `duplicate_candidates` (`409`) |
| `current_version: string` | `version_conflict` (`409`) |

Known slugs — the catalogue `strata_common::ProblemType`, the only list; domain errors
declare theirs through `strata_common::DomainError` and reach the wire via
`strata_api::wire::Problem::from_domain` — are `invalid_body`, `invalid_parameter`,
`invalid_name`, `unsupported_media_type`, `payload_too_large`, `not_acceptable`, `not_found`,
`route_not_found`, `method_not_allowed`, `bad_request`, `unauthorized`, `invalid_credentials`,
`forbidden`, `account_pending`, `account_rejected`, `account_disabled`,
`account_deletion_pending`, `password_change_required`, `version_conflict`,
`duplicate_candidates`, `username_taken`, `account_state_conflict`, `epoch_changed`,
`rate_limited` (sent with `Retry-After`) and `internal`. Clients must handle unknown slugs by `status`: the generated
client maps them to `ApiError::Other`. `detail` and `message` never contain user content.
Decode errors keep only the part of the message that comes from the target type (for example
`invalid type` or `missing field \`count\``).

## 5. Limits

Every body is checked structurally **before** it is decoded (iteratively, without allocating
per declared length), then decoded into the target type:

| Check | Default | Failure |
|---|---|---|
| Body size (per route, `MsgPackConfig::body_limit`) | 256 KiB | `413 payload_too_large` (checked against `Content-Length` and while reading) |
| Exactly one value, no trailing bytes | — | `422`, code `trailing_bytes` / `truncated` / `empty_body` |
| Nesting depth (arrays + maps) | 64 | `422`, code `depth_exceeded` |
| String length | 1 MiB | `422`, code `string_too_long` |
| `bin` length | 1 MiB | `422`, code `binary_too_long` |
| Array elements | 10 000 | `422`, code `array_too_long` |
| Map entries | 1 000 | `422`, code `map_too_long` |
| UTF-8 strings | — | `422`, code `invalid_utf8` |
| Extension types / reserved marker `c1` | — | `422`, code `extension_not_allowed` / `invalid_marker` |
| Shape matches the schema | — | `422`, code `schema_mismatch` with a JSON Pointer (`/count`) |

Routes override the defaults with `.app_data(MsgPackConfig { .. })` on a resource or scope.

## 6. Stream frames (WebSocket, D24)

Streams (`/events`, `/ask`, …) are WebSocket endpoints (`GET` + upgrade). The server sends
**one binary message per frame**. Each frame is a MessagePack map:

| Key | Type | Meaning |
|---|---|---|
| `v` | uint | envelope version, currently `1`. Clients reject newer versions. |
| `kind` | string | `data`, `error`, `reset` or `end`. Clients ignore kinds they don't know. |
| `seq` | uint | see below |
| `payload` | per kind | `data`: the stream's item type. `error`: a `Problem`. `reset`/`end`: `nil`. |

- `data`: `seq` is the item's sequence number and the resume key.
- `error`: terminal. `seq` is the last data seq sent. The server closes the socket.
- `reset`: the requested resume point is no longer retained, or is newer than the server's
  head (for example after a server restart). The client must refetch state and continues after
  `seq`, the server's head.
- `end`: the stream finished (for example an `/ask` answer). `seq` is the last data seq.

**Resume.** A client that reconnects sends `?resume_from=<last seq received>`. The server replays
the retained data frames after it (`ReplayBuffer`), or sends `reset`. Clients drop data frames
whose `seq` they have already seen.

**Liveness and backpressure.** The server pings every 15 s and closes with `1001` after 45 s
without any client traffic (pongs count). Frames are pulled from the source only as fast as the
socket drains. A send blocked for more than 10 s closes the socket with `1013` (slow consumer).
Text frames from the client are refused (`1003`). The client treats 45 s without a message as a
dead connection, then reconnects with exponential backoff and `resume_from`.

**Contract.** Each stream operation carries `x-strata-stream: {payload, frame}` and a `101`
response. The frame schemas are named components: `<Payload>Frame` is a `oneOf` of
`<Payload>DataFrame`, `ErrorFrame` and `ControlFrame`, discriminated by `kind`.

## 7. Conformance

`strata_api::contract::Contract` (feature `test-support`) validates any response, request, or
frame against the contract with JSON Schema 2020-12. It converts MessagePack to JSON, with
`bin` becoming a base64 string, and treats non-string map keys, duplicate keys, NaN and
extension types as violations. Formats (`date-time`, `ulid`) are checked. Object schemas are
closed, so undocumented fields fail. Every API test validates its responses this way (PLAN
§16.3). The generated-client tests do it through a `ResponseObserver`.
